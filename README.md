## 🗂️ Solution Architecture

Every solved problem is maintained inside the [`solutions`](./solutions) directory using a clean and scalable structure.

```text
LeetCode-Solutions/
│
├── .github/
│   └── workflows/
│       ├── leetcode_stats.yml
│       └── sync_leetcode.yml
│
├── scripts/
│   └── update_leetcode_stats.py
│
├── solutions/
│   ├── 0001-two-sum/
│   │   ├── README.md
│   │   └── solution.java
│   │
│   ├── 0141-linked-list-cycle/
│   │   ├── README.md
│   │   └── solution.java
│   │
│   ├── 0142-linked-list-cycle-ii/
│   │   ├── README.md
│   │   └── solution.java
│   │
│   └── ...
│
├── README.md
└── stats.json
```

Each problem directory is designed to contain:

```text
xxxx-problem-name/
├── README.md
└── solution.java
```

This keeps the repository **organized, searchable, scalable, and recruiter-friendly** as the number of solved problems grows.
